# Rent the plumbing, own the rules

**Status:** Research, as of 27 October 2026 · **Notes:** [the notes behind it](notes/)

During 2026, Microsoft (Agent 365, Entra Agent ID, Purview, Defender, Foundry), AWS (Bedrock AgentCore) and Google (Gemini Enterprise Agent Platform) converged on the plumbing a governed agent needs: an identity per agent with a named human sponsor, a registry with approval states, a gateway that denies by default and checks every tool call outside the agent's code, OpenTelemetry tracing, and managed evaluations. None of them ships the rules a business sets for its agents: how far each agent may act in each part of the business, who may approve that, and what evidence moves it up or down. LangChain Deep Agents (0.7.32, still pre-1.0) contributes a capable agent loop, but its safety controls run inside the agent process, allow by default, and have already had approval-bypass advisories. Nous Research's Hermes Agent shows how an agent can "live" through an always-on gateway, durable schedules, heartbeats that fire only when idle, and bounded memory, but its own security policy says nothing inside its process is a security boundary. So a5s rents identity, sandboxing, gateways and telemetry from whichever cloud hosts it, and owns a small, portable set of rules: policy outside the agent, levels that owners set, a tamper-evident ledger, and agents that live in records rather than in a process.

## Three clouds converge on identity, registries and deny-by-default gateways

All three clouds now ship the same five-part control plane: identity, registry, a gateway with policy, observability with evaluation, and a managed runtime. **None ships autonomy levels.** Microsoft handles autonomy through access patterns, approval tiers and runtime blocking ([CAF: govern and secure AI agents](https://learn.microsoft.com/en-us/azure/cloud-adoption-framework/ai-agents/governance-security-across-organization)). Google ties oversight to classes of action, such as "critical or irreversible" ones ([Google's Approach for Secure AI Agents](https://storage.googleapis.com/gweb-research2023-media/pubtools/1018686.pdf)). AWS's Agentic AI Security Scoping Matrix is a framework, not a product setting ([AWS](https://aws.amazon.com/ai/security/agentic-ai-scoping-matrix/)), and its critics argue that agency (what an agent can touch) and autonomy (whether a person approves) vary independently ([CSA](https://cloudsecurityalliance.org/blog/2025/12/16/enhancing-the-agentic-ai-security-scoping-matrix-a-multi-dimensional-approach)). A level that business owners set per agent, part and type of action is the gap a5s fills.

### Microsoft turns accountability into identity data

Agent 365 is a control plane, not a runtime. It reached general availability on **1 May 2026** at **$15 per user per month**, joining a registry in the Microsoft 365 admin center with Entra for identity, Purview for data and Defender for threats ([Agent 365 overview](https://learn.microsoft.com/en-us/microsoft-agent-365/overview); [Agent 365 Licensing FAQ](https://www.microsoft.com/licensing/faqs/122)). Its first lesson is that accountability can be stored as identity data and kept current. Every Entra agent identity and blueprint **must have a human sponsor**, and when a sponsor leaves, sponsorship passes to their manager "to prevent orphaned agents" ([Owners, sponsors, managers](https://learn.microsoft.com/en-us/entra/agent-id/agent-owners-sponsors-managers)). The registry shows "Agents without owners" as a headline tile ([Agent Registry](https://learn.microsoft.com/en-us/microsoft-agent-365/admin/agent-registry-overview)). a5s does the same: an agent whose owner and deputy have both gone stops.

The second lesson is the split between blueprint and instance. Admins can "apply a conditional access policy to all Sales Assistant Agents… disable all… revoke a permission grant for all" ([Entra: agent identities](https://learn.microsoft.com/en-us/entra/agent-id/agent-identities)). That's a5s's definition and instance: least privilege per instance, and one switch that suspends every instance of a misbehaving agent. Entra Agent ID also serves agents built elsewhere, with a documented sidecar for LangChain ([Integrate third-party agents](https://learn.microsoft.com/en-us/entra/agent-id/configure-third-party-agents)).

The third lesson is where reusing user tooling leaks. Purview audits "All agent-to-human, human-to-agent, agent-to-tools, and agent-to-agent interactions", but "Newly created content from Agent 365 doesn't inherit sensitivity labels from the source items", a DLP block is invisible to the agent, and Conditional Access can't see resources an agent reaches with an API key ([Purview for Agent 365](https://learn.microsoft.com/en-us/purview/ai-agent-365); [Conditional Access for agents](https://learn.microsoft.com/en-us/entra/identity/conditional-access/agent-id)). Defender's real-time protection for Copilot Studio is a policy decision point outside the agent that answers before each action ([Microsoft Security blog, 23 Jan 2026](https://www.microsoft.com/security/blog/2026/01/23/runtime-risk-realtime-defense-securing-ai-agents/)). And Microsoft's AI Red Team found that **"HitL bypass was the most consistently exploited failure mode"**, recommending approval prompts built from the actual tool calls, approvals tiered "by reversibility and blast radius", and watching for consent fatigue ([Microsoft Security blog, 4 Jun 2026](https://www.microsoft.com/en-us/security/blog/?p=147942)). Foundry hosted agents reached GA on 9 July 2026 and run LangGraph and LangChain projects unchanged ([Host LangGraph agents on Foundry](https://learn.microsoft.com/azure/foundry/how-to/develop/langchain-hosted-agents)).

### AWS moves enforcement outside the agent's code

AgentCore Policy, GA since **3 March 2026**, attaches deny-by-default Cedar policies to a Gateway that "intercepts all agent traffic … and evaluates each request … before allowing tool access", and AWS states the purpose plainly: "By moving security controls outside of agent code … reducing the risk of policy bypass through agent manipulation" ([Policy docs](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/policy.html)). The Identity token vault releases credentials only on proof of workload identity ([Identity features](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/key-features-and-benefits.html)), and the IETF's agent-identity draft states the principle as a rule: the LLM must never have access to agent or tool credentials ([draft-ietf-wimse-aims](https://datatracker.ietf.org/doc/html/draft-ietf-wimse-aims)).

**Dogwood**, a Cedar-compatible language launched on 6 August 2026, adds rules over time such as `count_within` ([AWS Open Source Blog](https://aws.amazon.com/blogs/opensource/introducing-dogwood-runtime-verification-for-ai-agents/)). But the history is scoped to a session whose ID "is supplied by the caller", and "starting a new session begins a new count" ([Temporal policies](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/policy-temporal.html)), so a limit that must hold across runs needs counts a5s keeps itself. Gateway rate limiting "fails open on transient errors" ([Release notes](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/release-notes.html)), fine for cost control and not for a control that must hold. Every Runtime configuration change creates an immutable version, which makes rollback a pointer move ([Runtime: how it works](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-how-it-works.html)). AgentCore is also the best-documented home for Deep Agents, but its sessions end after 8 hours by default, and one team found they were "losing history on every deploy" ([Runtime sessions](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-sessions.html); [Honeycomb](https://www.honeycomb.io/blog/prototype-production-aws-agentcore)).

### Google binds policy to a registry and a verified identity

Each Google agent gets "a unique, strongly attested cryptographic identity" in SPIFFE form, with 24-hour certificates, and when it acts for a user, "logs show both the agent's and the user's identities" ([Agent Identity overview](https://docs.cloud.google.com/iam/docs/agent-identity-overview)). Deleting an agent leaves its grants behind, and a redeployed replacement gets a new principal, so a5s keys agents on its own stable ID and treats the cloud principal as a changeable attribute. Agent Gateway and Agent Registry reached GA on **18 June 2026**: "All connections are blocked by default unless an explicit IAM policy grants access", and an unregistered tool simply can't be reached ([Agent Gateway overview](https://docs.cloud.google.com/gemini-enterprise-agent-platform/govern/gateways/agent-gateway-overview)). Rules can be written over tool attributes such as ReadOnly and Destructive instead of tool names ([Assign identity and IAM](https://docs.cloud.google.com/gemini-enterprise-agent-platform/govern/policies/assign-identity-iam)), which a5s copies as tools' risk attributes.

Google is explicit that controls with fixed answers and controls based on model judgement belong in different tiers, warning that defences based on model reasoning are "non-deterministic and cannot provide absolute guarantees" ([Google's Approach for Secure AI Agents](https://storage.googleapis.com/gweb-research2023-media/pubtools/1018686.pdf)). It also has the most developed picture of agents as coworkers: an Inbox for long-running work, and coworker agents with their own mailboxes acting "under its own identity rather than yours" ([Gemini at Work 2026](https://cloud.google.com/blog/products/ai-machine-learning/welcome-to-gemini-at-work-2026)). Its limits for a LangGraph-based a5s: Agent Gateway is managed only for Google's own runtimes so far ([Agent Gateway overview](https://docs.cloud.google.com/gemini-enterprise-agent-platform/govern/gateways/agent-gateway-overview)).

### Shared hazards

- **Connectors that write.** The AWS for SAP MCP Server creates, updates and deletes business objects, and Foundry exposes SAP connectors as MCP tools ([AWS What's New, 1 May 2026](https://aws.amazon.com/about-aws/whats-new/2026/05/aws-sap-mcp-amazon-bedrock/); [Ignite 2025 Book of News](https://news.microsoft.com/ignite-2025-book-of-news/)). An agent should write to a system of record only through its governed process.
- **Hidden model calls.** Managed memory, natural-language policy authoring and evaluations route model calls across regions, and "CloudWatch and AWS CloudTrail logs won't specify" where the work ran ([Cross-region inference](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/cross-region-inference.html)). Every managed feature that runs a model over agent data needs its own approval.
- **Churn.** Google renamed Vertex AI to Agent Platform in April 2026 ([Futurum](https://futurumgroup.com/insights/google-collapses-enterprise-ai-into-a-single-gemini-agent-at-gemini-at-work-2026/)). A portable core shields a5s from it.

## Deep Agents supplies the agent loop, not the security boundary

Deep Agents is an MIT-licensed agent harness built on LangChain's `create_agent` middleware and LangGraph, with a virtual filesystem, subagents, summarisation and offloading of context, Agent Skills, `AGENTS.md` memory and human-in-the-loop interrupts ([Deep Agents overview](https://docs.langchain.com/oss/python/deepagents/overview)). It's pre-1.0: **0.7.32 shipped on 23 October 2026** after 25 patch releases in about two months ([PyPI](https://pypi.org/project/deepagents/#history)).

The details of approval matter. LangChain's default batched mode matches decisions to tool calls by position, and its documentation gives the failure: **"A reviewer means to approve `write_file` and reject `execute_sql`, but sends `[reject, approve]`. The `DELETE` runs"** ([HITL concepts](https://docs.langchain.com/oss/python/concepts/human-in-the-loop)). On resume, "any code before the interrupt runs again", and a fork "does not roll back a thread" ([Interrupts](https://docs.langchain.com/oss/python/langgraph/interrupts); [Use time-travel](https://docs.langchain.com/oss/python/langgraph/use-time-travel)). So a5s keeps held calls outside the run, and every tool is idempotent.

The harness's own controls are permissive. File permission rules allow anything no rule matches and don't cover custom or MCP tools ([Permissions](https://docs.langchain.com/oss/python/deepagents/permissions)). In October 2026, GHSA-47w2-rfrr-wvq8 let an agent get around deny and interrupt rules in deepagents 0.5.2 to 0.7.24 ([advisory](https://github.com/langchain-ai/deepagents/security/advisories/GHSA-47w2-rfrr-wvq8)), and a chain disclosed by Check Point linked checkpointer SQL injection and unsafe deserialisation into remote code execution ([CSA research note](https://labs.cloudsecurityalliance.org/research/csa-research-note-langgraph-rce-chain-20260614-csa-styled/)). Under the StoreBackend's legacy default, "all users of the same assistant share the same storage" ([Backends](https://docs.langchain.com/oss/python/deepagents/backends)). A practitioner review states the right stance: Deep Agents "provides security controls, but it does not create a security boundary by itself" ([Wavect review](https://wavect.io/blog/langchain-deep-agents-review/)). The upside is portability: a deep agent runs on AgentCore Runtime, on Foundry hosted agents and on Google's runtime.

## Persistent agents should live in records, not processes

Hermes Agent (MIT, v0.22.5 on 23 October 2026) "lives" through five mechanisms ([README](https://github.com/NousResearch/hermes-agent/blob/main/README.md)): a long-lived gateway process per profile; conversations that "do not reset after inactivity or at a daily boundary"; sessions in SQLite with full-text search over past sessions; a small curated memory loaded as a frozen snapshot; and schedules, webhooks and a heartbeat that re-enter the conversation ([sessions](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/sessions.md); [memory](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/features/memory.md); [cron](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/features/cron.md); [heartbeat](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/features/heartbeat.md)). The heartbeat fires only when idle, merges missed ticks, may stay silent, and carries a "don't-invent-work guard". "Living" is an engineering pattern, not a property of the model.

Hermes is candid that this doesn't make it safe: **"The only security boundary against an adversarial LLM is the operating system. Nothing inside the agent process constitutes containment"** ([SECURITY.md](https://github.com/NousResearch/hermes-agent/blob/main/SECURITY.md)). "The agent can modify or delete any skill", and an outside audit found **4 Critical and 9 High issues in the default configuration** ([skills](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/features/skills.md); [CSA research note](https://labs.cloudsecurityalliance.org/research/csa-research-note-hermes-agent-cves-20260504-csa-styled/)). In OpenClaw, an injection could "append attacker instructions to HEARTBEAT.md", a file the agent re-reads every cycle ([The Hacker News](https://thehackernews.com/2026/02/openclaw-integrates-virustotal-scanning.html)), and OpenClaw later removed "inferred commitments", follow-ups the model extracted and pursued by itself ([OpenClaw automation](https://docs.openclaw.ai/automation)). Research finds that "a single adversarial write can exert long-term influence" on agent memory ([arXiv 2606.04329](https://arxiv.org/abs/2606.04329)).

The cloud runtimes have also rejected the process that lives forever: AgentCore sessions end after 8 hours by default and Google's Agent Runtime after 7 days ([AgentCore runtime sessions](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-sessions.html); [Google Cloud blog, 29 Jul 2026](https://cloud.google.com/blog/products/ai-machine-learning/whats-new-in-gemini-enterprise-agent-platform)). So an a5s agent lives in records: an identity, a register entry, obligations, triggers and conversations. Compute is the only temporary part. It's woken, given what it needs from the records, and discarded.

| Hermes or OpenClaw mechanism | Verdict | In a5s |
| --- | --- | --- |
| Always-on gateway; conversations never reset | Adapt | Durable identity, records and triggers; a fresh run for each piece of work, reading one conversation that never runs out of room |
| Jobs fired by webhook, with a schedule as fallback | Borrow | Events from the scenario's systems, and a sweep run by code |
| Heartbeat only when idle, ticks merged, silent when nothing changed | Borrow | The same sweep, which starts no model when nothing has changed |
| Each scheduled fire runs at most once | Borrow | The same, with one run per topic or case and idempotent tools |
| Agent creates its own schedules, or writes its own skills | Avoid | Schedules and skills change only through a tested release |
| Bounded memory frozen at session start | Borrow | Summaries and profiles people can see and correct |
| Approvals by an auxiliary model | Avoid | A person decides |
| Commitments inferred by the model | Avoid | Obligations computed from records, and promises the person confirms |
| The agent's own mailbox | Borrow | The agent's own identity, which says it's an AI |
| Scanners and allowlists inside the process | Heuristics only | Boundaries at the gateway, outside the agent |

## What a5s takes

| a5s part | From |
| --- | --- |
| Policy outside the agent, deny by default, failing closed | AgentCore Policy and Gateway, Google Agent Gateway, Defender's pre-tool hook |
| No credentials in the agent | AgentCore Identity's token vault, the IETF agent-identity draft |
| Definitions and instances, owners and deputies, suspension | Entra blueprints and sponsors, the registries' approval states |
| Tools' risk attributes | Google's ReadOnly and Destructive attributes |
| Counts a5s keeps itself, across runs | Dogwood's limits, which reset with each session |
| Held calls outside the run, and idempotent tools | LangGraph's interrupt and replay behaviour |
| Agents that live in records, with sweeps and promises people confirm | Hermes's mechanics, without its self-modification |
| Portability across clouds | Deep Agents runs on all three, and the clouds churn |
